# ASHEN CROWN · 灰烬王冠

**王冠坠落，灰烬永存。** 原创暗黑奇幻 Hex 战棋：灰牙兽人对抗暮誓精灵。包含四关主线「灰烬征途」（俘获、审讯、招募、士气）与原有的遭遇战「黑棘隘口」。

**立即游玩：https://grot666.github.io/ashen-crown/**

浏览器即开即玩，不需要账号、后端或付费资源。支持战术 AI 与同屏本地双人。21+ 是作品的成熟战争主题定位，不是官方年龄分级；没有露骨画面或成人内容。

## 开发与部署

需要 Node.js 22.19+（推荐最新 Node 22 LTS）与 npm。

```shell
npm ci
npm run dev
```

开发地址：`http://127.0.0.1:5173/ashen-crown/`。

```shell
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run preview
```

`main` 分支每次推送会运行规则测试、TypeScript 检查、生产构建、桌面与移动端浏览器测试，然后自动部署 GitHub Pages。PR 只验证，不部署。首次部署需在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。本仓库已配置；不需要 PAT、第三方部署平台或服务端密钥。构建输出为 `dist/`。

浏览器测试直接运行生产构建，请先执行 `npm run build`。测试包括移动、存档恢复、攻击／技能／结算、战报导出、本地双人、AI 回合、精灵先手交接、移动端布局及存储不可用提示。

如迁移仓库名称，修改 [vite.config.ts](./vite.config.ts) 中的 `base`，同时更新 Playwright 基础 URL、README 和 UI 源代码链接。

## 主线：灰烬征途

打开网站默认进入主线（`#/campaign`），遭遇战在 `#/skirmish`。玩家固定指挥灰牙氏族，名册、军团能力、士气与俘虏跨关保存。

| 关卡 | 地图 | 特殊规则 |
|---|---|---|
| 第一关「焦土渡口」 | 黑水河仅三处浅滩可渡 | **限时**：10 轮内全歼守军 |
| 第二关「余烬车队」 | 林道与王墟大道 | **护送**：灰烬图腾车抵达东侧营地，图腾车倒下即失败；第 3 轮北侧伏兵 |
| 第三关「月井死守」 | 半径 5 的圣地，四座高地环绕 | **坚守**：守满 8 轮；敌军连续两个回合占据中央月井即失败；第 3、5 轮两波增援 |
| 第四关「灰烬王座」 | 半径 5 的王座废墟 | **首领战**：击倒暮誓摄政（每回合恢复 4 生命，不可俘获）即胜 |

- **俘获**：主线中把敌人打到 0 生命时，按种子随机数判定是否生擒（存档内保存随机数游标，可复现）。基础概率由关卡决定；辅助单位 +15%，游侠/刃舞者 +5%，统帅 −10%；技能致命 −10%；敌方仅剩 ≤2 人时 +10%；「俘获之术」+10%；每层敌军抵抗 −8%；范围 5%–85%。目标列表会显示「致命 · 俘获 %」。
- **哥布林擒拿**：精灵单位带性别（♀/♂，按兵种默认、关卡可单独指定，档案面板标注）。哥布林的普通攻击或「绊索飞锤」命中**女性精灵**时一击制服并**必定俘获**（不消耗随机数、不受敌军抵抗影响），目标列表显示「必杀 · 俘获 100%」，战场上带「擒」徽记。暮誓摄政（女性首领）与护送目标不受此规则影响——首领仍不可俘获，只按普通伤害结算。仅在主线生效；遭遇战没有俘获。被俘者只进入既有的俘虏营流程。
- **俘虏营**：每名俘虏三选一。**审讯**：解锁一项军团能力（按兵种优先：守望者→誓约破绽、游侠→高地暗哨、刃舞者→刃舞步法、先知→月泉秘方，其余依次为巡逻路线、俘获之术；全部解锁后改为士气 +5）。**招募**：编入名册（上限 10），保留兵种、归属兽人阵营，肖像背景随归属变色并带「降」徽记。**酷刑**：抽象处理，仅一行纪事；士气 +15，但敌军抵抗 +1（此后敌军生命 +2、俘获率 −8%）。
- **士气**（0–100，初始 50）：≥80 全军攻击 +1、生命 +3；≥60 攻击 +1；40–59 无；20–39 首回合 AP −1；<20 攻击 −1 且首回合 AP −1。胜利 +10，失利 −10，每名永久阵亡 −4。
- **初始军团**：督军、黑兽人、兽人小子 ×2、哥布林、萨满（6 人）。前三关奖励：哥布林、黑兽人、兽人小子。
- **v3 平衡**：黑兽人 生命 48 / 攻击 13 / 护甲 5、「破阵斧」18；兽人小子 生命 32 / 攻击 11 / 护甲 2、「淬火飞斧」12（遭遇战同样生效）。AI 对 AI 模拟（18 组士气/减员/能力组合）胜率：第一、二关 100%，第三关 89%，第四关 94%。
- **名册**：胜利时阵亡的单位永久离队（督军除外）；失利或撤退不会损失单位，可重打。前三关胜利各奖励一名援军。
- **存档 v2**：`ashen-crown:campaign:v2`（主线）与 `ashen-crown:skirmish:v2`（遭遇战）。旧版 `ashen-crown:campaign:v1` 首次加载时自动迁移为遭遇战存档；无法迁移时明确提示并重置。
- **平衡**：`tests/balance.test.ts` 让双方都使用战术 AI 打完四关：基础军团（仅关卡奖励、无能力、士气 50）必须获胜且有明显损耗；只出战 3 人必须失败。

## 指挥手册

- **选择与移动**：点击己方单位 / 军团列表；金色格显示本次移动的 AP 总成本。移动、攻击、技能共用 AP。普通单位 3 AP，游击单位 4 AP。
- **攻击**：点击红色角标目标或右侧目标列表；消耗 2 AP。可多次行动，只要 AP 足够。没有随机命中。
- **技能**：点击单位专属技能，再选择高亮目标；消耗 2 AP。伤害技能无视护甲和地形；治疗可对自身施放，但不可复活或超出生命上限。
- **冷却**：在己方回合开始时减 1；冷却 2 意味着跳过下一己方回合。
- **回合**：点击「结束回合」或按 `E`；AP 在己方回合开始时恢复。兽人固定先行，AI 模式可选任一阵营。同屏双人不支持网络联机。
- **胜负**：消灭所有敌军获胜；统帅阵亡不会直接败北。双方各行动一次为一轮，40 轮后仍有双方存活则平局。
- **快捷键**：`H` 打开规则，`Esc` 取消技能或选择；`Tab` + `Enter` 可操作战场和按钮。AI 在弹窗打开时暂停；1× / 2× 只改变行动展示速度，不改变难度。

| 地形 | 移动 AP | 防御 | 额外效果 |
|---|---:|---:|---|
| 灰烬荒原 | 1 | 0 | 无 |
| 枯语密林 | 2 | +2 | 掩护 |
| 黑岩高地 | 2 | +1 | 远程普通攻击伤害 +2；阻挡经过它的射线 |
| 失落王墟 | 1 | +1 | 适合争夺的低成本掩体 |
| 幽影深潭 | 不可通行 | — | 不阻挡射线 |

普通伤害 `max(2, 攻击 + 远程高地加成 − 护甲 − 目标地形防御)`。射程为六边形距离；中间高地阻挡普通攻击及技能，起终点高地不阻挡。单位阻挡移动，但不阻挡射线。规则完全确定性，利于复盘和测试。

## 架构与扩展

```text
src/
  engine/
    types.ts      # Hex、单位（含 owner/状态/加成）、技能与行动的严格类型
    content.ts    # 两阵营、11 种兵种（含哥布林、首领与图腾车）、地形及技能数据
    scenarios.ts  # 遭遇战与四关主线：地图、布阵、目标、增援、奖励
    campaign.ts   # 名册、俘虏营、军团能力、士气、战后结算
    rng.ts        # 可复现的种子随机数（仅用于俘获判定）
    hex.ts        # axial 坐标、距离、邻格、射线、像素投影
    game.ts       # 不可变状态转换、加权寻路、战斗、回合与胜负
    ai.ts         # 合法行动评分：击杀、伤害、治疗、接敌、地形、威胁
  storage.ts      # 存档 v2（主线 + 遭遇战）、逐字段校验、v1 迁移
  art.ts          # 原创 SVG 军徽、人物与图标
  board.ts        # SVG 战场、地形、单位及可操作范围
  portraits.ts    # 全部兵种的手绘 SVG 半身像（按兵种/归属/性别变化，无 defs/id）
  main.ts         # DOM 界面、输入、AI 调度、弹窗、自动存档与战报
  style.css       # 响应式主题、键盘焦点与减少动态效果适配
tests/
  engine.test.ts
  storage.test.ts
  browser/game.spec.ts
.github/workflows/deploy.yml
```

规则引擎不引用 DOM、存储、时钟或网络。`applyAction(state, action)` 返回新的状态或明确错误，不修改输入；玩家与 AI 使用相同的验证和行动入口，寻路高亮与移动成本共享算法。

### 添加兵种

1. 在 `UnitKind` 添加键，在 `UNITS` 添加完整 `UnitDefinition`。
2. 在 `scenarios.ts` 的关卡数据中部署它；界面与 AI 自动读取属性、射程和技能。阵营由单位的 `owner` 决定，而不是兵种。
3. 添加行为测试。若修改兵种编成、地图或存档形状，同时升级存档版本和校验器，避免旧存档误用新规则。

### 添加机制

现有技能通过 `SkillDefinition` 的 `effect: 'damage' | 'heal'` 判别接口工作。新增状态效果时，在类型联合、`canSkill`、`applyAction`、AI 评分和测试中增加显式分支，而不是在 UI 里另写规则。新增地形在 `Terrain`、`TERRAIN` 和战场美术中定义。

AI 是可解释的启发式战术评分，不是机器学习或穷举搜索，也不暗中读取额外信息。当前地图固定，没有战争迷雾。双方数值非对称，第一期不宣称竞技平衡。

## 存档、隐私与资源

所有对局仅保存在当前浏览器的 `localStorage`；每个成功行动后自动保存。刷新可续局，包括 AI 进行中的回合；新战役会覆盖旧存档。清理站点数据会丢失进度。不可用 / 损坏的存档会明确提示，不会阻止游玩。导出文本战报可保留整场行动记录。

移动端战场可在自身区域横向滚动，不会撑破页面。所有图形均为项目原创 SVG，无商业图片或第三方游戏素材；无运行时 JavaScript 依赖。字体可选从 Google Fonts 加载，失败时使用系统字体，不影响游戏；托管方仍可能保留基础访问日志。
